# Проблемы и решения

Документ описывает, какие именно поломки лечит репозиторий, как они проявляются, почему возникают и что делает каждый скрипт.

---

## P1. Ассеты не загружаются: QUIC (HTTP/3) дропается провайдером

### Симптомы

- Модели, текстуры, звуки, анимации не появляются или появляются частично.
- Аватары без одежды, аксессуаров, волос.
- В логе `%LOCALAPPDATA%\Roblox\logs\*_last.log`:

```
[DFLog::HttpTraceError] CURLOPT_ERRORBUFFER: Operation timed out after 59999 milliseconds with 0 bytes received
[DFLog::HttpTraceError] HttpResponse(#162 ...) time:60015.7ms (net:59999.4ms) error:5
    message:HttpError: Timedout url:{ "https://fts.rbxcdn.com/v2/sc3/..." }
[DFLog::AssetProvider] AssetResolutionWorkflow ... failed
```

### Причина

Клиент Roblox (0.7xx) качает ассеты по HTTP/3 поверх UDP 443. На части провайдеров QUIC обрабатывается «наполовину»:

1. Initial-пакеты и рукопожатие проходят;
2. дальше пакеты в обе стороны дропаются (DPI/шейпер);
3. клиент не получает ни данных, ни ошибки и ждёт полный таймаут — 60 секунд на файл;
4. очередь загрузки встаёт целиком: пока висят N файлов, новые не начинаются.

Важно: TCP к тем же адресам при этом **полностью работает** — поэтому «интернет же есть» и сторонние программы ничего не замечают.

### Как доказать

`service.bat` → `4` (захват 90 с, играть в Roblox). Скрипт снимет UDP 443 через `pktmon` и покажет по каждому адресу отправленные/полученные байты. Признак проблемы:

```
3.164.240.39   отправлено 411664 Б (864 пак.)   получено 122310 Б (126 пак.)
```

где 122 КБ пришли в первую секунду (рукопожатие), дальше — ноль. Односторонний поток.

### Решение

`scripts/quic.ps1 -Mode block`:

- создаёт правило файрвола «исходящий UDP 443 → Block» для `RobloxPlayerBeta.exe` и `RobloxStudioBeta.exe` всех найденных версий;
- включает активный профиль файрвола с разрешающими политиками по умолчанию (поведение сети не меняется, применяются только явные правила);
- запоминает исходное состояние профиля для отката.

Клиент больше не может поднять QUIC и уходит в TCP/HTTP2.

### Результат (замер на реальной машине)

| Метрика | До | После |
|---|---|---|
| Скачано с CDN | 0 Б | 22 МБ за сессию |
| Таймаутов `fts.rbxcdn.com` (`net:>=50 c`) | 47–49 | 0 |

Модерированные ассеты (`AssetDelivery403`, «Asset has not been reviewed») в эту статистику не входят — это ограничения Roblox на конкретные модели, а не сеть.

## P2. Мёртвые edge-адреса CDN: не грузятся картинки, иконки, превью

### Симптомы

- Иконки игр, превью, картинки в меню и на сайте не появляются.
- Часть адресов CDN не отвечает на TCP вообще (таймаут 3–5 с вместо 30 мс).
- «Народные» фиксы с `hosts` помогают на время, потом снова ломается.

### Причина

`tr.rbxcdn.com` / `fts.rbxcdn.com` — CNAME на CloudFront/Akamai. Разные DNS-резолверы возвращают разные наборы edge-адресов. У конкретного провайдера часть этих адресов недоступна (маршрут/фильтрация/вывод узла из строя). Клиент берёт адрес из DNS и вешает на нём соединение.

Проверка вручную:

```powershell
# часть адресов отвечает за 30 мс, часть — не отвечает вовсе
node -e "..."        # или service.bat -> 3
```

### Решение

`scripts/hosts.ps1 -Mode apply`:

1. Опрашивает 5 DoH-резолверов (Cloudflare, Google, Quad9, AdGuard, AliDNS) по каждому домену.
2. Собирает уникальные адреса.
3. Проверяет каждый: TCP-соединение + TLS-рукопожатие с нужным SNI, замер времени.
4. Сортирует по задержке, оставляет до 4 лучших на домен.
5. Пишет управляемый блок в `hosts` (предварительно делая резервную копию).
6. Сторонние записи для этих доменов (старые фиксы на 40+ адресов) предлагает закомментировать — иначе они возвращают мёртвые адреса в пул.

Расширенный вариант с 28 UDP-резолверами: `python tools\edge_collector.py --check`.

## P3. «Поставил фикс — после обновления Roblox всё сломалось снова»

### Причина

Roblox ставит каждую версию в отдельную папку `Versions\version-<hash>` и запускает новый `RobloxPlayerBeta.exe`. Правило файрвола привязано к полному пути файла, поэтому на новую версию оно не действует.

### Решение

`scripts/schedule.ps1 -Mode install` создаёт задачу `RobloxUnlocker-Refresh` (SYSTEM, highest):

- при старте системы и далее каждые 30 минут вызывает `refresh.ps1`;
- добавляет правила для новых версий, удаляет правила для версий, которых больше нет;
- раз в 3 дня пересобирает `hosts` с живыми адресами.

## P4. «Как понять, что у меня именно это, а не что-то другое»

`service.bat` → `3` (диагностика) и `4` (захват).

Диагностика отвечает на вопросы:

- стоит ли фикс и покрывает ли он текущую версию Roblox;
- что было в последней сессии: сколько зависаний `>= 50 c`, сколько ошибок ассетов, на каких хостах;
- живы ли адреса `fts`/`tr` из системного DNS и DoH.

В конце она печатает одну строку `ВЕРДИКТ: ...` — этого достаточно для решения:

| Вердикт | Значение |
|---|---|
| `ФИКС НУЖЕН` | признаки поломки есть, можно ставить |
| `ФИКС НЕ НУЖЕН` | признаков нет |
| `НЕДОСТАТОЧНО ДАННЫХ` | Roblox не запускался или сессия слишком короткая |
| `УЖЕ РАБОТАЕТ` | фикс стоит и последняя сессия чистая |
| `НУЖНО ОБНОВИТЬ HOSTS` | QUIC отключён, но часть CDN-адресов мертва |
| `ПРОБЛЕМА С ИГРОВЫМ СЕРВЕРОМ` | ассеты в порядке, но провайдер режет UDP игровых серверов |
| `ЭТОТ ФИКС НЕ ПОМОГ` | проблема не в QUIC/CDN, нужен обход блокировок |

Захват отвечает на главный вопрос: уходит ли QUIC-трафик и приходит ли ответ.

## P5. Телепорт между серверами: «сетевая ошибка» после смены сервера

### Симптомы

- Игра идёт нормально, ассеты грузятся.
- В конце матча/раунда игру перекидывает на другой сервер — и вместо загрузки появляется
  «Disconnected» / «сетевая ошибка», клиент возвращается в меню.
- Ручной вход в тот же плейс работает.

### Причина

При обычном входе клиент подключается к игровому серверу через **UDMUX** (`128.116.x`), и этот
путь обычно проходит. При телепорте Roblox может выдать **прямой публичный адрес RCC** —
чаще всего AWS `eu-central-1` (`18.197.x`, `18.199.x`, `35.159.x`, `63.179.x`). Провайдер
пропускает рукопожатие, а затем **перестаёт пропускать UDP в обе стороны**.

В логе это выглядит так:

```
! Joining game '...' place ... at 63.179.58.66
RbxTransport token or port is empty. ... rbxTransportPort = 64200
Transport selection: ... selectedTransport=RakNet, rccPort=63135
Connection accepted from 63.179.58.66|63135
Replicator created for player 63.179.58.66|63135
AckTimeout: Last Packet received time: 20003 ms
Connection lost - Cannot contact server/client
```

Ключевое: `Connection accepted` есть (первые пакеты прошли), `Server RobloxGitHash` и репликации
нет, а через 20 секунд — `AckTimeout`. Правила файрвола RobloxUnlocker тут ни при чём: они режут
только **UDP 443**, а игровые серверы слушают порты `50000–65535`.

### Решение

Фикс ассетов (QUIC + hosts) это **не лечит** — его и не должно.

Рабочие варианты:

1. **VPN на время игры** — надёжно, потому что UDP уходит в туннель и DPI не может его разобрать.
   Минус — пинг растёт.
2. **UDP-desync в zapret** — добавляет фейковые UDP-пакеты так, что DPI не классифицирует поток.
   Пинг не меняется, но требует установленного zapret и настраивается вручную.

### Как включить UDP-desync для игровых серверов (zapret)

1. В `lists\ipset-all.txt` добавить диапазоны, где живут игровые серверы. Для AWS Франкфурта
   (`eu-central-1`) это ~450 префиксов; проще всего взять их из
   `https://ip-ranges.amazonaws.com/ip-ranges.json`, отфильтровав `region = eu-central-1`.
2. Убедиться, что в конфиге zapret есть правило вида:

```
--filter-udp=1024-65535 --ipset="...\lists\ipset-all.txt"
--dpi-desync=fake --dpi-desync-any-protocol=1
--dpi-desync-fake-unknown-udp="...\bin\ACTIVE_GAME_UDP.bin"
```

   В пресетах `general*.bat` оно уже есть, но `ipset-all.txt` по умолчанию содержит заглушку.
3. Перезапустить `winws.exe` (ipset читается только при старте).
4. Зайти в игру и проверить телепорт.

Откат: вернуть старый `ipset-all.txt` и перезапустить `winws.exe`.

Важно: список диапазонов зависит от того, где Roblox размещает серверы. Если телепорт снова
сломается — проверьте в логе новый адрес и его регион, и добавьте диапазоны этого региона.

## Чего репозиторий НЕ делает

- Не обходит блокировку серверов Roblox (`apis.roblox.com`, игровые серверы). Если не работает вход в аккаунт или подключение к игре — нужен другой инструмент (zapret/GoodbyeDPI/VPN).
- Не меняет аккаунт, настройки приватности и регион.
- Не «ускоряет» интернет и не обещает меньший пинг.
- Не ставит сторонних драйверов и не требует выключать антивирус.

## Почему не fastflags

`ClientAppSettings.json` с `DFIntHttp3FtsReqs=0` / `DFIntHttp3CdnReqs=0` не работает: клиент Roblox не читает локальные fastflags (они остались только в Studio). Проверено на пакетах — UDP 443 продолжает идти, таймауты остаются. Поэтому используется блокировка на уровне ОС.
